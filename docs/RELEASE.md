# إعداد إصدار أرض وتوقيعه

تحتاج هذه الخطوات إلى المتصفح فقط، ويمكن تنفيذها من التابلت. لا ترفع ملف المفتاح أو كلمات
المرور إلى Git أو إلى أي مكان عام. مفتاح التوقيع هو ما يسمح بتثبيت تحديثات التطبيق فوق النسخة
السابقة مع الاحتفاظ ببياناتها؛ إذا فُقد المفتاح فلن يمكن توقيع تحديث متوافق.

## 1. إنشاء المفتاح مرة واحدة

1. افتح المستودع على GitHub، ثم انتقل إلى **Actions**.
2. اختر **Make keystore** من قائمة workflows ثم **Run workflow** على فرع `main`.
3. بعد نجاح التشغيل، افتح صفحة التشغيل ونزّل artifact باسم **Ard-keystore-setup**.
4. افتح الملف `ard-keystore-secrets.txt` داخل ZIP. يحتوي على أربعة أسطر: `KEYSTORE_BASE64`،
   `KEYSTORE_PASSWORD`، `KEY_ALIAS`، و`KEY_PASSWORD`.
5. احتفظ بنسخة آمنة وخاصة من هذا الملف خارج المستودع (مثل مساحة تخزين خاصة موثوقة). لا تشاركه
   ولا تضعه في رسالة أو issue أو commit. يستطيع من يملك هذه القيم توقيع نسخ باسم تطبيقك.

أنشئ المفتاح مرة واحدة فقط. لا تشغّل **Make keystore** مجددًا للمفتاح نفسه؛ فالمفتاح الجديد لا
يستطيع تحديث النسخة الموقعة بالمفتاح القديم. احتفظ بنسخة احتياطية آمنة من ملف المفتاح وقيمه.

## 2. إضافة أسرار GitHub Actions

1. من صفحة المستودع افتح **Settings**.
2. من القائمة الجانبية اختر **Secrets and variables** ثم **Actions**.
3. تحت **Repository secrets** اضغط **New repository secret**.
4. افتح `ard-keystore-secrets.txt` في نافذة أخرى أو في عارض الملفات على التابلت. أنشئ سرًا لكل
   سطر، مستخدمًا الاسم كما هو والقيمة بعد علامة `=` دون تغيير:
   - `KEYSTORE_BASE64` — قيمة Base64 الطويلة كاملةً.
   - `KEYSTORE_PASSWORD` — كلمة مرور مخزن المفتاح.
   - `KEY_ALIAS` — قيمة alias، وهي `ard`.
   - `KEY_PASSWORD` — كلمة مرور المفتاح.
5. احفظ كل سر عبر **Add secret**. تحقق من ظهور الأسماء الأربعة في قائمة الأسرار؛ لا تحاول
   عرض قيمها، إذ لا يعرضها GitHub بعد حفظها.

إذا كان أحد الأسرار ناقصًا، يفشل إعداد الإصدار برسالة توضح ضرورة إضافة الأسرار الأربعة معًا.
إن لم يُضف أي منها، يظل بناء debug متاحًا ويُتخطى إصدار release.

## 3. حذف workflow إنشاء المفتاح

بعد حفظ الأسرار الأربعة بأمان والتحقق منها، احذف الملف
`.github/workflows/make-keystore.yml` من المستودع عبر واجهة GitHub ثم أنشئ commit للحذف. هذا
الـworkflow مخصص للتهيئة الأولية فقط؛ حذف الملف لا يحذف المفتاح المحفوظ لديك أو أسرار GitHub.
نزّل نسخة artifact واحفظ المفتاح قبل الحذف، لأن artifact مؤقت وينتهي بعد سبعة أيام.

## 4. بناء APK إصدار

1. افتح **Actions** واختر workflow **Android APK**.
2. اضغط **Run workflow** على فرع `main` وانتظر اكتمال التشغيل بنجاح.
3. نزّل artifact **Ard-release** للحصول على APK إصدار موقع. يبقى artifact **Ard-debug** متاحًا
   للتجربة والتطوير، لكنه موقّع بمفتاح debug ولا يستخدم للتحديثات الرسمية.
4. ثبّت APK الإصدار على الجهاز الذي عليه النسخة السابقة. يجب أن يكون التطبيق السابق موقعًا
   بالمفتاح نفسه؛ عندها يمكن التحديث فوقه مع بقاء بياناته. يرفع workflow رقم الإصدار تلقائيًا
   مع كل تشغيل جديد حتى يقبله Android كتحديث.

ملاحظة مهمة: نسخة debug التي بُنيت قبل إعداد هذا المفتاح موقعة بمفتاح debug مختلف، لذلك لا يمكن
تحديثها مباشرةً بهذا الإصدار. Android يرفض اختلاف التوقيع؛ قد يتطلب الانتقال الأول إزالة نسخة
debug، ما قد يحذف بياناتها. صدّر/انسخ أي بيانات مهمة قبل ذلك إن كان التطبيق يخزن بيانات محلية.
من أول تثبيت لإصدار موقّع بهذا المفتاح فصاعدًا، استخدم مفتاح الإصدار نفسه لكل تحديث.

لم أتحقق من بناء إصدار أو من تحديث فعلي على جهازك؛ يتطلب ذلك إنشاء المفتاح، حفظ أسرار المستودع،
وتجربة التثبيت على الجهاز.
